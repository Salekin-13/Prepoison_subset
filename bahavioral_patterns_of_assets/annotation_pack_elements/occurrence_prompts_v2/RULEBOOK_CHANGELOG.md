## Differences from `SITES_draft_v2.md`, with the reason for each

### Kept SITEs, changed

| SITE | Difference from v2 | Reason |
|---|---|---|
| all | Every SITE has a `kind`: **primary** (the part of a statement or declaration) or **add-on** (how the name is written: FIELD_USE, INDEXED_NAME, INDEX, ATTR_PREFIX, PART_SELECT). Add-ons go in the same entry as the primary SITE, or alone where none matches. | v2 has no rule for combining SITEs; "apply every site that fits" gave inconsistent combinations. The only v2 combination rule is PART_SELECT's "together with". |
| DECL_PORT | Component port lists and generics get *no entry*; port clause span by counting parentheses (in `annotate_rules.md` section D since `1df37b88a29b`); the port modes include `linkage`. | v2 says component entries are not elements but gives no instruction. v2 lists four modes; `linkage` compiles (e2). A semicolon after the last port fails (k5). |
| DECL_SIGNAL | The five declarative parts that can hold a signal. Their spans were taught here until `cab0c37b2720`; section D gives them since `1df37b88a29b`. | v2 names them loosely. Signals compile in entity, block, generate and package declarative parts (d1–d3, d7) and fail in process and function ones (d4, d5). A function body inside the architecture has its own `begin` (d6). |
| PROCESS_TRIG | v2's "Neither form names an element, so neither gives an element this site" is replaced. The label gets no entry; an unlabeled process still gives PROCESS_TRIG; `process (all)` gives none. The block ends at the first `end process`; a labeled process can end with either `end process;` or `end process <label>;` (the block span is in section D since `1df37b88a29b`). | The v2 sentence can be read as "an unlabeled process gives no site", and the generated rulebook read it that way. A process cannot hold another process (t3). A labeled process ending `end process;` compiles (e1; corpus `neorv32_bus.vhd` line 691); an end label without a header label fails (e4). |
| EDGE_CHECK, IF_COND | If statement and branch spans taught (in section D since `1df37b88a29b`); an `if ... generate` condition gives an *empty list*. | Nested if/elsif/else compiles (t4). A signal in an if-generate condition only warns and elaborates (t6), so an element can occur there; an edge function there fails (t2). |
| DECL_FIELD, FIELD_USE | DECL_FIELD only on the line declaring the base. At `<base>.<field>`, the base gets FIELD_USE alone and the field gets its own SITEs, as any other element would (since `34d10274b852`: a field slice that is the whole right-hand side is PART_SELECT alone). One FIELD_USE entry per field selection, even on one line. | v2's "Where the same text is read as an occurrence of the base, that is FIELD_USE instead" led the generated rulebook to put DECL_FIELD on every dotted use. `bus_req_i` at trng line 171 reaches three fields and got one entry. |
| LHS_PROC | Branches include `else`, and case alternatives are listed too, each with its span (in section D since `1df37b88a29b`, where an alternative is its own kind, not a branch). | v2 names only branches opened by EDGE_CHECK or IF_COND; the corpus has else branches and 16 case statements. |
| LHS_CONC | "an if statement is only written inside a process block" becomes "(or a function or procedure)". | An if statement in a function compiles (e5); v2's own IF_COND already says so. |
| DIRR_ASS | An element with an index or a range is not the whole right-hand side: an index gives INDEXED_NAME, a range gives PART_SELECT, each alone where no primary SITE matches. | Implied by v2's "no index, no range", but v2 names no SITE for such an occurrence. |
| INDEX | Add-on. Only an element inside the parentheses; the array before them is INDEXED_NAME; an attribute prefix inside them is ATTR_PREFIX. | v2 leaves open whether INDEX excludes value SITEs. v2's WHEN_EXPR says "anywhere inside", so INDEX is written together with the primary SITE. The BNF separates `indexed_name`'s prefix from its expressions, and `attribute_name` has its own prefix. The run tagged `sample_cnt'left` as INDEX. |
| PART_SELECT | Worded as a VHDL slice name; add-on; alone for a slice that is the whole right-hand side. Conflict rule 7 reworded to match (`c503e0de726c`); its basis quote is still v2's "Recorded together with the site ... not instead of it", which this rule overrides for a whole-right-hand-side slice. | "Part select" is not a VHDL term (the BNF says `slice_name`). v2's PART_SELECT context ("together with the site") and the DIRR_ASS reading conflicted: 11 whole-RHS slices got empty lists in the 2026-09-15 run. PART_SELECT alone for them confirmed by the user, 2026-09-15. Conflict rule 7 and CHECK 8 still said "always together" until `c503e0de726c`; run 5 had 2 such slices tagged DIRR_ASS + PART_SELECT. |
| LHS_PROC, LHS_CONC, INDEX | An element giving a position inside the parentheses of an assignment target is not the target: no LHS_PROC or LHS_CONC; its add-on SITEs (INDEX or ATTR_PREFIX, with PART_SELECT where sliced; FIELD_USE for a base) are written alone. Conflict rule 0 says the target is the name before its parentheses. Not from v2. | Decided by you, 2026-09-15, after run 5: 7 entries at `neorv32_cache.vhd` 383-423 got LHS_PROC + INDEX, and two reviews disagreed on whether the rulebook decided it. v2's LHS_PROC basis ("The `<element_label>` is on the left of `<=`") does not settle it either way. |
| CONFLICT_RULES | 16 rules. First: how primary and add-on SITEs combine. Others: EDGE_CHECK vs IF_COND; PROCESS_TRIG and EDGE_CHECK are separate occurrences; INDEX / INDEXED_NAME / ATTR_PREFIX / PART_SELECT; DECL_FIELD vs FIELD_USE; component ports; the case sites; ASSOC_ACTUAL; VAR_RHS_OPERAND. | v2 has no conflict rules. |

### v2 sentences deliberately left out of the rulebook

| v2 sentence (short) | Reason |
|---|---|
| DECL_PORT "The statement declares one element…" | One entry can declare several names (v2's own next sentence); the trigger covers it. |
| DECL_PORT "`<type>` specifies the data type." | Not needed to tag. |
| DECL_SIGNAL "…carry values between parts of a design"; "…cannot be seen from outside it"; "…visible to every design unit…" | What a signal is for, and visibility: not needed to tag. |
| PROCESS_TRIG "Neither form names an element…" | Ambiguous; replaced (see PROCESS_TRIG above). |
| EDGE_CHECK "A process that holds an edge condition is a clocked process." | Names what a process is for; `annotate_rules.md` section G forbids that in a Role. |
| DECL_FIELD "Where the same text is read as an occurrence of the base, that is FIELD_USE instead." | Caused the DECL_FIELD error; replaced (see DECL_FIELD above). |
| RHS_OPERAND "An expression built from operators is combinational logic…" | Describes behaviour; forbidden in a Role. |
| INDEX "…a read-only memory…" | Names what the constant is for; the rest is kept. |
