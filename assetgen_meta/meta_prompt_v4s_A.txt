CHANGES TO INTEGRATE: execution-prompt rules [FIXED: carry their meaning into the execution prompt without weakening it]

X1 Role coverage when mapping a conceptual asset to its structural references.
"For each conceptual asset, trace its value along its path through this entity, and identify the element that plays each of these
roles, when such an element exists: (a) the point where the value enters the entity or is set, meaning an input port through which
it arrives, or the element that this entity's logic or software writes it into; (b) the element that holds it as state; (c) the
element where a decision about it is computed; (d) the output port through which it leaves the entity. Report the element for every
role that exists, not only one of them. Elements between these roles that only copy, synchronize, or delay the value, with no
decision of their own, are carriers: they are secondary and are not reported."
Basis: IEEE P3164 white paper, section 3.1.2: the structural assets are "the RTL code that produces" an asset's value "and stores
and transports its value"; section 4: the points where an asset "can be observed or influenced". Elements that only help transfer an
asset between those points are secondary (SAIF, VTS 2021).

X2 Strict meaning of "stores".
"An element stores a value when it holds state that this entity sets or updates and keeps across clock cycles. A register that only
re-times, synchronizes, or delays another element's value is a carrier, not storage; report the element whose value it re-times.
Use the realization label "stores" only for elements that store in this sense."
Basis: IEEE P3164 white paper, section 3.1.2: structural assets produce, store, or transport a value; a register that only
re-times a value transports it rather than storing it, and elements that only transfer an asset are secondary (SAIF).

X3 Implementation mechanics are not targets.
"An element whose only role is to sequence or time an operation, such as a bit or cycle counter that advances a shift, a handshake
or strobe pulse, a flag used only for pacing, or a clock-enable tick, is implementation mechanics. It is not a primary asset unless
the RTL shows that it holds or decides a security-relevant value, for example a counter whose value decides a timeout or a lockout."
Basis: SAIF defines primary assets as what designers "esteem ... as a definitive target for protection" (its examples are keys,
random numbers and seeds, identifiers, private data, and configuration bits for operational and privilege modes); LAsset defines them
as "the direct target of an attack".

"A shared bus or register-access interface (address, write data, byte enables, strobe, acknowledge, read data) and the decoding
