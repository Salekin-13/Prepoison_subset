X1 — Role coverage
Edited sections: 9.e, Identify structural references; 10, Validation.

Added sentences in 9.e:
- “For each conceptual asset, trace its value along its path through this entity, and identify the element that plays each of these roles, when such an element exists: (a) the point where the value enters the entity or is set, meaning an input port through which it arrives, or the element that this entity's logic or software writes it into; (b) the element that holds it as state; (c) the element where a decision about it is computed; (d) the output port through which it leaves the entity.”
- “Report the element for every role that exists, not only one of them.”
- “Elements between these roles that only copy, synchronize, or delay the value, with no decision of their own, are carriers: they are secondary and are not reported.”
- “Basis: IEEE P3164 white paper, section 3.1.2: the structural assets are "the RTL code that produces" an asset's value "and stores and transports its value"; section 4: the points where an asset "can be observed or influenced".”
- “Elements that only help transfer an asset between those points are secondary (SAIF, VTS 2021).”

Replacement sentence in 10:
- “Check that the element for every existing entry or setting, state-holding, decision-computation, and entity-exit role has been reported for each concept, applying the stated exclusions and without expanding the output to secondary connectivity.”

Replaced seed sentence:
- “Check that all demonstrated eligible realization points were considered, without expanding the output to secondary connectivity.”

X2 — Strict meaning of storage
Edited sections: Definitions; 2, Observation; 9.e, Identify structural references; 10, Validation.

Added sentences in Definitions:
- “Storage: An element stores a value when it holds state that this entity sets or updates and keeps across clock cycles.”
- “A register that only re-times, synchronizes, or delays another element's value is a carrier, not storage; report the element whose value it re-times.”
- “Use the realization label "stores" only for elements that store in this sense.”
- “Basis: IEEE P3164 white paper, section 3.1.2: structural assets produce, store, or transport a value; a register that only re-times a value transports it rather than storing it, and elements that only transfer an asset are secondary (SAIF).”

Replacement sentence in 2:
- “Capturing a value in a register is storage only when this entity sets or updates it and keeps it across clock cycles, not when the register only re-times, synchronizes, or delays another element's value.”

Replacement sentences in 9.e:
- “"stores": the element holds the concept's value as state that its entity sets or updates and keeps across clock cycles; a register that only re-times, synchronizes, or delays another element's value is a carrier, not storage.”
- “A storing element remains a realization point even when it captures unchanged data, provided it holds state in the defined sense rather than merely re-timing, synchronizing, or delaying another element's value; report the element whose value a carrier register re-times.”

Added sentence in 10:
- “"stores" must mean state that this entity sets or updates and keeps across clock cycles; a register that only re-times, synchronizes, or delays another element's value is a carrier, not storage.”

Replaced seed sentences:
- “Capturing a value in a register is storage, even if its input expression is unchanged data.”
- “"stores": the element retains the concept's value or state.”
- “A storing element remains a realization point even when it captures unchanged data.”

X3 — Implementation mechanics
Edited sections: Definitions; 5, Asset definition; 9.e, Identify structural references; 10, Validation.

Added sentences in Definitions:
- “Implementation mechanics: An element whose only role is to sequence or time an operation, such as a bit or cycle counter that advances a shift, a handshake or strobe pulse, a flag used only for pacing, or a clock-enable tick, is implementation mechanics.”
- “It is not a primary asset unless the RTL shows that it holds or decides a security-relevant value, for example a counter whose value decides a timeout or a lockout.”
- “Basis: SAIF defines primary assets as what designers "esteem ... as a definitive target for protection" (its examples are keys, random numbers and seeds, identifiers, private data, and configuration bits for operational and privilege modes); LAsset defines them as "the direct target of an attack".”

Added sentence in 5:
- “Do not identify implementation mechanics as conceptual assets unless the RTL shows that they hold or decide a security-relevant value.”

Added sentence in 9.e:
- “Do not report an element whose only role is sequencing or timing unless the RTL shows that it holds or decides a security-relevant value.”

Added sentence in 10:
- “Implementation mechanics must not be reported unless the RTL shows that the element holds or decides a security-relevant value.”

Removed seed sentence in Definitions, jointly addressed by X3, X4, and X5:
- “Clock, clock-enable and reset inputs, and ports whose record type carries complete bus transactions, are not structural references in this way.”

The blanket clock-enable exclusion in 9.e is also removed through the replacement listed under X5:
- “Clock, clock-enable, and reset inputs are not structural references under the consumed-input rule.”

X4 — Shared access paths
Edited sections: Definitions; 2, Observation; 9.e, Identify structural references; 10, Validation.

Replacement sentences in Definitions:
- “Shared access paths (X4): A shared bus or register-access interface (address, write data, byte enables, strobe, acknowledge, read data) and the decoding around it are the path through which software reaches this entity's registers.”
- “They are secondary supports that transfer the assets, not assets: report the registers and decisions inside the entity instead, and name any port whole, never one of its fields.”
- “A security attribute carried with a transaction (a privilege level, a debug-mode flag, or a source identifier) is different: when this entity decides on it, for example to allow, deny, or bypass an access, that decision is a conceptual asset; report the element inside the entity that computes or holds the decision, and if no such element exists, keep the concept and leave its structural references empty.”
- “Basis: SAIF (VTS 2021, p2): "the bus and the decoder are the secondary supports helping to transfer the primary asset".”
- “CWE-1302, CWE-1311, CWE-1317 and CWE-1318 treat security attributes carried by transactions as security-relevant.”

Replacement sentence in 2:
- “Record shared-access-path patterns and sub-block connection-field patterns without yet classifying assets.”

Replacement and added sentences in 9.e:
- “An output port through which the concept leaves its entity is an eligible exit, including when driven from another realization point in that entity, unless the shared-access-path exclusion applies.”
- “Shared bus or register-access interfaces and their decoding are secondary; do not use them as readback exits or write-setting points, and report the registers and decisions inside the entity instead.”
- “Identify shared access paths from their role in software register access, whether their elements are record-typed or scalar.”
- “For a security attribute carried with a transaction on which this entity decides, report the element inside the entity that computes or holds the decision; if none exists, keep the concept and leave its structural references empty.”
- “Do not use a whole internal record to bypass restrictions applicable to its shared-access-path or carrier contents.”

Replacement and added sentences in 10:
- “If it is a decision on a transaction's security attribute, are its references limited to the elements inside the entity that compute or hold the decision, with an empty list if none exists?”
- “No shared bus or register-access interface element or its decoding may be present, whole or by field.”
- “A whole record must not be used to evade shared-access-path or carrier exclusions.”

Removed or replaced seed sentences in Definitions:
- “Clock, clock-enable and reset inputs, and ports whose record type carries complete bus transactions, are not structural references in this way.”
- “Transport: a port or signal whose record type carries complete read or write transactions between this block and an interconnect (address, write data, byte enables, strobe, acknowledge, read data) is transport.”
- “Do not report it, whole or by field.”
- “Do not use it as the exit of a value that a register holds and software can read back, or as the element that sets a value written into this block.”
- “Report the element inside the block that stores or decides the value.”
- “A port is a single candidate: name it whole; never report a field of a port.”

Replaced seed sentence in 2:
- “Record transport patterns and sub-block connection-field patterns without yet classifying assets.”

Replaced seed sentences in 9.e:
- “An output port through which the concept leaves its entity is an eligible exit, including when driven from another realization point in that entity, unless transport exclusion applies.”
- “Transport records are excluded whole and by field.”
- “Do not use a transport port as a readback exit or write-setting point; identify the eligible element inside the block that stores or decides the value.”
- “Identify transport from record structure and complete transaction behavior, not particular field spellings.”
- “Do not categorically exclude scalar ports merely for being bus-related.”
- “Do not use a whole internal record to bypass restrictions applicable to its transported or carried contents.”

Replaced seed sentences in 10:
- “No transport element may be present, whole or by field.”
- “A whole record must not be used to evade transport or carrier exclusions.”

X5 — Clock and reset infrastructure
Edited sections: Definitions; 9.e, Identify structural references; 10, Validation.

Added sentences in Definitions:
- “Clock and reset infrastructure: Global clock and reset inputs are infrastructure that interacts with every register of the entity; they are secondary, not primary assets of this entity.”
- “The exception is an entity whose function is to produce or control a clock or a reset: there, the clock and reset elements that implement that function are structural references of it.”
- “Basis: SAIF: secondary assets are "infrastructures that closely interact with the primary assets"; CWE-1206 (Power, Clock, Thermal, and Reset Concerns) treats clock and reset control as a security concern.”

Replacement sentence in 9.e:
- “Global clock and reset inputs are secondary infrastructure, except in an entity whose function is to produce or control a clock or a reset, where the clock and reset elements implementing that function are structural references of it.”

Added sentence in 10:
- “Global clock and reset inputs must be excluded unless the entity's function is to produce or control a clock or a reset and those elements implement that function.”

Removed seed sentence in Definitions, jointly addressed by X3, X4, and X5:
- “Clock, clock-enable and reset inputs, and ports whose record type carries complete bus transactions, are not structural references in this way.”

Replaced seed sentence in 9.e:
- “Clock, clock-enable, and reset inputs are not structural references under the consumed-input rule.”

X6 — Gating elements as decisions
Edited sections: Definitions; 9.e, Identify structural references; 10, Validation.

Replacement sentences in Definitions:
- “An element that only passes the value through unchanged, with no decision of its own, carries the asset but is not its structural reference.”
- “Elements that only pass the value through unchanged, with no decision of their own, are not primary, but secondary assets.”
- “Secondary asset: an element that only passes a primary asset's value through unchanged, with no decision of its own, or an internal signal or register that influences a primary asset or could violate its security objective without itself realizing an Established conceptual asset.”

Added sentences in Definitions:
- “Gating decisions: An element that decides whether a value may pass, such as a gate, mux, or enable driven by a mode, an enable, an override, or a select, is where an availability or integrity decision is computed.”
- “It plays the decision role, not the carrier role, and is reported.”
- “Only an element that passes a value through unchanged, with no decision of its own, is a carrier.”
- “The decoding of a shared access path covered by X4 stays secondary.”
- “Basis: IEEE P3164 white paper, section 3.1.1, availability question: elements that could gate an output port or the use of an input port; in its GPIO example the mux gates are the conceptual asset.”

Replacement sentences in 9.e:
- “"computes": the element realizes a computation or decision defining the concept, including a decision about whether a value may pass.”
- “Do not report intermediates that only pass a value through unchanged, with no decision of their own.”

Added sentence in 10:
- “An element that decides whether a value may pass must be treated as a decision point, not a carrier, except for decoding of a shared access path.”

Replaced seed sentences in Definitions:
- “An element that only passes the value along, or gates it on the way, carries the asset but is not its structural reference.”
- “Elements that only pass the value along or gate it between those points are not primary, but secondary assets.”
- “Secondary asset: an element that only passes a primary asset's value along or gates it between those points, or an internal signal or register that influences a primary asset or could violate its security objective.”

Replaced seed sentences in 9.e:
- “"computes": the element realizes a computation or decision defining the concept.”
- “Do not report intermediates that merely forward, route, or gate an already-defined value.”

X7 — Input ports

Added sentences in 9.e:
- “An input port is where the value enters the entity; its realization label is "sets".”
