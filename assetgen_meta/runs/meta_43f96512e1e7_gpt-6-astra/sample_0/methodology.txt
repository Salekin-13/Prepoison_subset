  With: “An eligible input port through which the value enters the entity is where that value is set.”
- Replaced: “Secondary asset: an element that only passes a primary asset's value along or gates it between those points, or an internal signal or register that influences a primary asset or could violate its security objective.”
  With: “Secondary asset: an element between realization points that only passes a primary asset's value along, synchronizes or delays it, or gates it, with no decision of its own, or an internal signal or register that influences a primary asset or could violate its security objective.”

DEFINITIONS — additions:
- “Role coverage (X1): For each conceptual asset, trace its value along its path through this entity, and identify the element that plays each of these roles, when such an element exists: (a) the point where the value enters the entity or is set, meaning an input port through which it arrives, or the element that this entity's logic or software writes it into; (b) the element that holds it as state; (c) the element where a decision about it is computed; (d) the output port through which it leaves the entity.”
- “Report the element for every role that exists, not only one of them.”
- “Elements between these roles that only copy, synchronize, or delay the value, with no decision of their own, are carriers: they are secondary and are not reported.”
- “The entry and exit roles never apply to a transport interface (see X4).”
- “Basis: IEEE P3164 white paper, section 3.1.2: the structural assets are "the RTL code that produces" an asset's value "and stores and transports its value"; section 4: the points where an asset "can be observed or influenced".”
- “Elements that only help transfer an asset between those points are secondary (SAIF, VTS 2021).”

X3 — Implementation mechanics
Sections edited: DEFINITIONS; 5. Asset definition; 9.e. Identify structural references; 10. Validation.

DEFINITIONS — shared replacement with X4 and X5:
- Replaced: “Clock, clock-enable and reset inputs, and ports whose record type carries complete bus transactions, are not structural references in this way.”
  With: “Apply the implementation-mechanics (X3), transport (X4), and clock/reset infrastructure (X5) rules to these input roles.”

DEFINITIONS — additions:
- “Implementation mechanics (X3): An element whose only role is to sequence or time an operation, such as a bit or cycle counter that advances a shift, a handshake or strobe pulse, a flag used only for pacing, or a clock-enable tick, is implementation mechanics.”
- “It is not a primary asset unless the RTL shows that it holds or decides a security-relevant value, for example a counter whose value decides a timeout or a lockout.”
- “Basis: SAIF defines primary assets as what designers "esteem ... as a definitive target for protection" (its examples are keys, random numbers and seeds, identifiers, private data, and configuration bits for operational and privilege modes); LAsset defines them as "the direct target of an attack".”

5. Asset definition — addition:
- “Apply the implementation-mechanics rule (X3) when identifying concepts as well as structural references.”

9.e. Identify structural references — shared replacement with X5:
- Replaced: “Clock, clock-enable, and reset inputs are not structural references under the consumed-input rule.”
  With: “Apply the implementation-mechanics rule (X3) to clock-enable inputs and the clock/reset infrastructure rule (X5) to clock and reset inputs.”

10. Validation — additions:
- “Does any claimed sequencing or timing target satisfy the implementation-mechanics rule (X3), rather than representing mechanics alone?”
- “Any sequencing or timing element must hold or decide a security-relevant value under the implementation-mechanics rule (X3).”

X4 — Transport interfaces
Sections edited: DEFINITIONS; 9.e. Identify structural references; 10. Validation.

DEFINITIONS — shared replacement with X3 and X5:
- Replaced: “Clock, clock-enable and reset inputs, and ports whose record type carries complete bus transactions, are not structural references in this way.”
  With: “Apply the implementation-mechanics (X3), transport (X4), and clock/reset infrastructure (X5) rules to these input roles.”

DEFINITIONS — transport-rule replacement:
Removed these seed sentences:
- “Transport: a port or signal whose record type carries complete read or write transactions between this block and an interconnect (address, write data, byte enables, strobe, acknowledge, read data) is transport.”
- “Do not report it, whole or by field.”
- “Do not use it as the exit of a value that a register holds and software can read back, or as the element that sets a value written into this block.”
- “Report the element inside the block that stores or decides the value.”

Added these replacement sentences:
- “Transport (X4): A bus or interconnect transaction interface, meaning a port or signal whose record type carries complete read or write transactions (address, write data, byte enables, strobe, acknowledge, read data), is transport: it carries transactions that belong to other blocks, so it is a secondary support and never a primary asset.”
- “This holds also in a module whose function is to switch, route, arbitrate, or monitor such transactions: there, the assets are the module's own arbitration, routing, and monitoring decisions and the state that holds them, not the transaction interfaces.”
- “In every module, report the registers and decisions inside the entity instead of the transport interface, and name any port whole, never one of its fields.”
- “A security attribute carried with a transaction (a privilege level, a debug-mode flag, or a source identifier) is different: when this entity decides on it, for example to allow, deny, or bypass an access, that decision is a conceptual asset; report the element inside the entity that computes or holds the decision, and if no such element exists, keep the concept and leave its structural references empty.”
- “Basis: SAIF (VTS 2021, p2): "the bus and the decoder are the secondary supports helping to transfer the primary asset".”
- “CWE-1302, CWE-1311, CWE-1317 and CWE-1318 treat security attributes carried by transactions as security-relevant.”

9.e. Identify structural references — additions:
- “The transport exclusion (X4) also applies to switching, routing, arbitration, and monitoring modules; report their own decisions and the state that holds them, not their transaction interfaces.”
- “For a decision on a security attribute carried with a transaction, report only the element inside the entity that computes or holds the decision; if no such element exists, keep the Established concept with an empty structural list.”

10. Validation — additions:
- “In switching, routing, arbitration, and monitoring modules, the references must identify the module's own decisions and the state that holds them, not transaction interfaces (X4).”
- “A decision on a transaction-carried security attribute must map only to an internal element that computes or holds it; if none exists, the Established concept must retain an empty structural list (X4).”

X5 — Clock and reset infrastructure
Sections edited: DEFINITIONS; 9.e. Identify structural references; 10. Validation.

DEFINITIONS — shared replacement with X3 and X4:
- Replaced: “Clock, clock-enable and reset inputs, and ports whose record type carries complete bus transactions, are not structural references in this way.”
  With: “Apply the implementation-mechanics (X3), transport (X4), and clock/reset infrastructure (X5) rules to these input roles.”

DEFINITIONS — additions:
- “Clock/reset infrastructure (X5): Global clock and reset inputs are infrastructure that interacts with every register of the entity; they are secondary, not primary assets of this entity.”
- “The exception is an entity whose function is to produce or control a clock or a reset: there, the clock and reset elements that implement that function are structural references of it.”
- “Basis: SAIF: secondary assets are "infrastructures that closely interact with the primary assets"; CWE-1206 (Power, Clock, Thermal, and Reset Concerns) treats clock and reset control as a security concern.”

9.e. Identify structural references — shared replacement with X3:
- Replaced: “Clock, clock-enable, and reset inputs are not structural references under the consumed-input rule.”
  With: “Apply the implementation-mechanics rule (X3) to clock-enable inputs and the clock/reset infrastructure rule (X5) to clock and reset inputs.”

10. Validation — addition:
- “Global clock and reset inputs must be excluded as infrastructure unless the entity's function is to produce or control a clock or reset and the elements implement that function under the clock/reset infrastructure rule (X5).”
