# Hard assets: why the generator finds or misses each one

31 ground-truth assets found in fewer than 7 of 9 runs (seed, seed+examples, +map section). Written by two Claude reader agents from the generator's outputs, the RTL and the seed prompt (line numbers = the seed exec_prompt.txt). Where an asset is never named in a run that misses it, the deciding rule is inferred from the RTL shape, not from the model's words (the seed forbids listing excluded cases, L269).

## neorv32_cache / ctrl.buf_sync  (difficult; cause: concept_not_formed)
- **What it does:** It is a field of the clocked control record ctrl (L101, L108; the whole record is captured by ctrl <= ctrl_nxt at L126). It remembers a fence request (L138 'ctrl_nxt.buf_sync <= ctrl.buf_sync or host_req_i.fence'), is tested at L168 to enter S_CLEAR, and is cleared in S_CLEAR (L220).
- **Found:** Found in 6 of 9 runs (c 1/3, ism 2/3, ismr 3/3), labelled 'stores' every time. Key: c = m7e194es0c, ism = m7e194es0ism, ismr = m7e194es0ismr. c r0 <Buffered fence/sync indicator (ctrl.buf_sync) that triggers cache clear>. ism r0 <Buffered control flags (buf_req, buf_sync, buf_err, buf_dir) that gate flows>. ism r2 <Buffered host-request and fence indicators ... (ctrl.buf_req, ctrl.buf_sync)>. ismr r0 <Buffered fence/synchronization flag that triggers cache clear>. ismr r1 <Buffered fence/synchronization flag (request to clear/sync the cache)>. ismr r2 <Buffered request control flags that determine buffering, sync/clear, direct-bypass and download error handling>.
- **When missed:** Missed in c r1, c r2 and ism r1. Neither 'ctrl.buf_sync' nor 'buf_sync' appears anywhere in those 3 outputs. The clear flow is still covered, by ctrl.state (stores, <FSM state that selects ... clear>) and by cache_o.cmd_clr (computes/sets, <Cache control commands ... clearing>). The sibling buffer ctrl.buf_err is reported in all 3 misses. So the pending-fence buffer never got a concept of its own, and the clear decision was carried by ctrl.state and cache_o.cmd_clr.
- **Deciding rule:** seed L214: 'Do not treat an influencing signal or register as primary unless it independently realizes an Established concept.' Once a sync concept exists, L205 ('"stores": the element retains the concept's value or state.') gives 'stores', as in 6 of 6 hits.
- **Conflicting rule:** seed L97: 'Do not turn a dependency into a primary asset merely because corrupting it could affect an Established concept.' (buf_sync feeds the ctrl.state transition.)
- **Explanation:** Measured: when the concept exists the field is always reported as 'stores'. When it is missed it is never named. The outputs do not show which rule blocked the concept, because seed L269 forbids listing excluded cases. ismr is the best arm here (3/3). Both maps give storage 'none' for this field, because the clock edge assigns the whole record, and that did not suppress it. There is no case where ism found it and ismr missed it, so the map section did not suppress it.

## neorv32_cache / we_i  (difficult; cause: rule_ambiguity)
- **What it does:** It is the byte-write-enable input of the sub-entity neorv32_cache_memory (L330), driven by cache_o.we (L289). Each bit decides whether one byte lane of data_mem_b0..b3 is written on the clock edge (L413, L416, L419, L422).
- **Found:** Found in 4 of 9 runs (c 2/3, ism 2/3, ismr 0/3), always 'sets', and always inside a concept where the write enable is itself the value. c r1 <Cache-memory control commands and write enables that cause line writes, invalidation, and clearing>. c r2 <Byte write-enable mask (we) that gates writes to cached bytes>. ism r0 <Memory write data and byte-enable controls (what is written and which bytes)>. ism r1 <Memory write control and write data used to populate cache lines>.
- **When missed:** Missed in c r0, ism r2 and ismr r0, r1, r2. It is named in all 5, always inside the 'cached data contents' concept, as the condition of the byte writes ('writes bytes into data_mem_b0..b3 when we_i bits are set'). That concept reports data_mem_b0..b3 (stores) and rdata_o (exit port). None of the 5 misses has a write-enable concept. In ismr r0 the controller-side fields cache_o.we and cache_o.data are reported as 'sets' instead, so there the value is realised upstream.
- **Deciding rule:** seed L13: 'An element that only passes the value along, or gates it on the way, carries the asset but is not its structural reference.' This applies when we_i is read as the gate of the stored data.
- **Conflicting rule:** seed L13: 'An input port whose value this entity itself reads, to store it, compute from it, or decide on it, is where that value enters' (so realization 'sets'). The ism worked example at exec_prompt L813 says: 'per_en, per_we and per_addr are sets because omsp_gpio consumes them to decide write eligibility.'
- **Explanation:** Measured: all 4 hits treat the write enable as its own value, and all 5 misses treat we_i as the gate of stored data. How the concept is framed decides which of the two L13 sentences applies. ismr (ism 2/3, ismr 0/3): the likely suppressor is relation_section L23, 'Verify whether it defines the concept or merely gates an already-defined value. Influence alone is not a primary realization.' The E3 map entry shows only four GATES records (to data_mem_b0..b3) and the functionality 'each bit gates a corresponding byte write'. The same section also says (L27) 'Apply the full consumed-input rule regardless of relationship label.', so it pulls both ways. Caveat, measured: in ismr the sibling memory inputs clr_i, inv_i and new_i also fell from 3/3 (ism) to 1/3, so this is part of a wider drop of the memory-side inputs. csr_we_i in cfu has the same GATES-only shape and stays at 3/3 in ismr. Inference: the difference may be that cache's write enable has an upstream eligible producer in the same file (cache_o.we).

## neorv32_cache / addr_i  (difficult; cause: realised_elsewhere)

- **Found:** Found in 5 of 9 runs (c 1/3, ism 2/3, ismr 2/3), always 'sets', and always added to an address concept next to ctrl.tag, ctrl.idx and ctrl.ofs (stores) and cache_o.addr. c r2 <Cached address components (tag / index / offset) used for lookup, memory indexing and bus addresses>. ism r0 <Address fields used to select cache block and build bus requests>. ism r1 <Requested address components and the computed memory address used to select a cache line>. ismr r0 appears under both <Buffered request address (tag, index, offset) and derived cache/memory address ...> and <Stored tag values per cache block used for hit comparison>. ismr r2 <Buffered request address (tag, index, offset) used to form cache and bus addresses>.
- **When missed:** Missed in c r0, c r1 and ismr r1. In those runs the address concept exists but reports only ctrl.tag, ctrl.idx and ctrl.ofs (stores), and addr_i is not named. Missed in ism r2 too, where it is named as a source ('acc_tag/acc_idx/acc_off are derived from addr_i') and the slices acc_tag, acc_idx and acc_off are reported as 'sets' in its place. In all 4 misses the value is realised elsewhere.
- **Deciding rule:** seed L265: 'Check that all demonstrated eligible realization points were considered, without expanding the output to secondary connectivity.' The trace stops at the stored copy on the controller side.
- **Conflicting rule:** seed L13: 'One conceptual asset usually has several structural references along its path', together with the consumed-input rule ('compute from it' gives 'sets'). Against it, seed L218: 'An input used only for unchanged forwarding is not an eligible setting point.' A slice can be read as forwarding.
- **Explanation:** Measured: the address concept was formed in all 4 misses. In 3 of them it is realised only at ctrl.tag, ctrl.idx and ctrl.ofs; in 1 it is realised at acc_tag, acc_idx and acc_off. The ism r2 choice breaks seed L57 ('Merely assigning a value to a combinational intermediate does not establish a setting or computation point.'), so the path rules are applied loosely. ism and ismr both find it 2 of 3 times, so the map section did not change it.

## neorv32_cache / cache_o.cmd_dir  (never; cause: gt_convention)
- **What it does:** This name is not declared in the supplied RTL. The record cache_o_t (L76-L83) has the fields cmd_clr, cmd_inv, cmd_new, addr, data and we, and no cmd_dir. The GT row's rationale talks about the cache_o record in general.
- **Found:** Found in 0 of 9 runs.
- **When missed:** It is never named: 'cmd_dir' appears in no output. With the scorer's strict matching it can be credited only by an exact 'cache_o.cmd_dir' or by the whole record 'cache_o', and 'cache_o' is reported in 0 of 9 runs. The model reports the real command fields instead: cache_o.cmd_inv, cmd_clr and cmd_new 8/9 each, plus the direct-access flag ctrl.buf_dir 4/9. All of these are scored as false positives.
- **Deciding rule:** seed L254: '"asset rtl" must be an exact name from the closed set.' Also seed L19: 'Nothing else can be a structural asset.'
- **Conflicting rule:** For the only other credited route (the whole record), seed L225: 'Do not use a whole internal record to bypass restrictions applicable to its transported or carried contents.'
- **Explanation:** The GT names an element that does not exist in this RTL. Inference: the row was probably made on a different NEORV32 version. Under name matching, no prompt can recover it without inventing a name. Measured: this row, together with inval_i, caps recall on neorv32_cache at 4 of 6 GT entries.

## neorv32_cache / inval_i  (never; cause: gt_convention)
- **What it does:** This name is not declared in the supplied RTL. Its meaning, invalidating the addressed block, is carried by inv_i of neorv32_cache_memory (L325; tested at L382 to clear the valid bit). inv_i is driven by cache_o.cmd_inv (L284), which is set after a download error (L255).
- **Found:** Found in 0 of 9 runs.
- **When missed:** It is never named. The RTL's invalidate input is inv_i. The model reports inv_i ('sets') in 6 of 9 runs and the command field cache_o.cmd_inv in 8 of 9, usually in a concept such as <Cache control commands (clear / invalidate / new entry)>. Every one of those reports is scored as a false positive. So the same meaning is realised elsewhere under its real name.
- **Deciding rule:** seed L254: '"asset rtl" must be an exact name from the closed set.'
- **Explanation:** Measured: the value is found under its real name inv_i in 6 of 9 runs and scored as a false positive each time. So this GT row costs recall (one false negative in every run) and also precision (an inv_i false positive in 6 runs). Renaming inval_i to inv_i in the GT would fix it. That is a GT decision, not a prompt one.

# Recurring patterns

- **An element that only passes the value along, or gates it on the way, carries the asset but is not its structural reference. / Do not infer a supplied entity's internal computation from an unavailable implementation or from a connection alone.** (seed exec_prompt.txt L13 and L226 (also L59, L138)) — 4 difficult assets: lsu_err, lsu_wait, lsu_mar and alu_add. These are neorv32_cpu wires between sub-blocks whose code is not supplied. Cause: concept_not_formed.. These wires have no in-entity behaviour, so their meaning comes only from names. No concept forms in 5-6 of the 9 runs, and when one does form the label is a stretch ('stores'). Measured counter-example: pmp_fault is also wired-only but has a local driver ("pmp_fault <= '0'", L427) and a security-sounding name, and it is found 8 of 9 times. The map section adds to the suppression. Over all 15 modules the 6 GT wires other than pmp_fault and fifo.free fall from 10/18 run slots in ism to 1/18 in ismr, and non-GT wired-only elements from 26/81 to 11/81.

- **An input port whose value this entity itself reads, to store it, compute from it, or decide on it, is where that value enters / An input used only for unchanged forwarding is not an eligible setting point.** (seed L13 and L218 (label L206)) — 2 assets: dbi_i (difficult) and firq_i (chance). Cause: exclusion_fires. The same 'itself reads' condition also blocks rs3_i and active_i, which are counted under the GT pattern.. Inputs that go straight into a sub-block whose code is not supplied are excluded, while the locally read siblings mti_i, mei_i and msi_i are found 8/9 each. The 5 hits come from stretching 'reads' to 'consumed by the sub-block', and 1 of them cites a port map that does not exist. This is a gap between the prompt and the GT convention: the GT counts forwarded inputs as assets.

- **... or gates it on the way, carries the asset but is not its structural reference. / Do not mistake a condition operand for the result of that condition.
